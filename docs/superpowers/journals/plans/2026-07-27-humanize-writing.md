### rev-imp-1 · finding [fixed] · seed_config.py dotted-key seeding corrupted flow-style and 4-space-indented configs

seed_key located the deepest existing ancestor line and inserted the new child block after it assuming (a) the ancestor is a bare block-mapping line and (b) children indent at 2*depth. A flow-style ancestor (quality: {gate: {...}}) got an indented block appended after the flow line -> unparseable YAML; a 4-space-indented quality: block got a 2-space lint: inserted, silently re-nesting the existing gate: under the new lint: (config corruption with no error). Fix: after locating the ancestor, require a bare block-mapping line (re.fullmatch over optional-comment-only after the colon) — flow mappings and scalar ancestors (quality: true) now exit 1 with the existing seed-it-manually error, file untouched; child indent is derived from the ancestor's first existing child line when present, falling back to ancestor_indent+2. Regression tests: test_flow_style_ancestor_errors_and_leaves_file_untouched, test_scalar_ancestor_errors_and_leaves_file_untouched, test_four_space_indent_keeps_gate_a_sibling_of_lint (tests/unit/test_seed_config.py).

### rev-line-numbers · decision · Lint warnings print counts only — the spec's 'line numbers' promise amended away

The spec said warnings print 'with counts and line numbers'. The density checks (em-dash, negative parallelism, triads per 1000 words) are aggregates over the whole prose body — there is no single line to point at — and per-hit line numbers for the remaining checks would buy little (the messages carry the exact term/opener to grep for). Rather than bolt line tracking onto _prose_only (which reflows lines), the spec sentence in docs/superpowers/specs/2026-07-27-humanize-writing-design.md was amended to 'Warnings print with counts, exit 0.' Implementation and spec now agree.
