# Stickers — port frank's private sticker set into blog-craft

Spec: `docs/superpowers/specs/2026-08-03-sticker-generation-design.md`

## What this plan does

frank runs two prompt-composition engines: blog-craft's shared one for covers,
and a 474-line private fork under `blog/_private/frank-stickers/` for its
die-cut sticker set. This plan retires the fork. After it ships, frank's 18
stickers compose through blog-craft's engine, byte-identically, and the
capability is available (off by default) to any blog-craft blog.

## Why the fork has to go now, not later

It is already broken. `frank/scripts/lib/contact_sheet.py` is untracked and was
last touched by frank's `bd0415e6 frank P7 — cutover: frank's blog now
generated by blog-craft (#600)` — the cutover deleted it, because blog-craft's
`generate-images.py` brought its own `_contact_sheet`. frank's
`generate-stickers.py` imports it at module top:

```python
sys.path.insert(0, str(REPO_ROOT / "scripts"))
from lib.contact_sheet import compose_contact_sheet   # ModuleNotFoundError
```

So sticker *generation* has raised `ModuleNotFoundError` since that cutover.
`build-sheets.py` does not import it, so sheet rebuilding still works — which
is exactly why the breakage went unnoticed: the visible artifact still
regenerates from already-generated images.

This sharpens what "no behavioral changes" means for this plan. The baseline is
not "what the script does today" (it crashes); it is **the composition rule as
written in its source**, which is intact and fully readable. Phase 5 pins that
rule with goldens derived from the real `compose_prompt()`.

## The five things that do not port for free

Established during the brainstorm, each verified against source:

1. **The mood frame has no expression in config.** frank wraps a per-entry
   free-form mood in `f"Frank's expression: {s['mood']}."`
   (`generate-stickers.py:53`). `compose.py`'s passthrough returns the raw
   value. Phase 1 adds a `_template` directive.
2. **Sticker and cover `base_character` contradict each other** — covers say
   "flat-top hair", stickers say "NOT a hard blocky / square flat-top". They
   cannot share a layer name. Sticker layers are namespaced `sticker_*`.
3. **The shared engine is destructive.** It writes the last variant to the
   entry's `output:` (`generate-images.py:351`); frank's sticker script writes
   only to `regen/` and never touches the curated master. Porting stickers as
   ordinary entries would destroy hand-picked artwork. Phase 2 adds `--out`.
4. **No model fallback, no HTTP timeout** in `_gen_bytes`. frank's script has
   both. Phase 2 adds `image.fallback_model` and `image.timeout_ms`.
5. **No print/DPI-aware layout code anywhere.** `build-sheets.py` is the only
   genuinely new code: 2480×3508 at 300 DPI, centered 3×3, `dpi` written into
   the PNG so printing at 100% keeps the `#1b4332` keyline a true cut path.

## Measured facts the plan relies on

Verified by importing frank's real `compose_prompt` with its five API-only
imports stubbed (2026-08-03):

- all 18 stickers compose to exactly **8 sections**;
- reference payloads are **3 or 4** images (3 when `clothing_anchor` is null);
- the mood section is exactly
  `Frank's expression: satisfied — sleepy half-smile, eyes half closed.`;
- `border_spec` is the **last** section, after `scene`;
- prompt lengths are ~4.6k chars.

`--dry-run` cannot produce goldens: it truncates to 300 chars
(`generate-stickers.py:101`). Goldens come from `compose_prompt()` directly.

## Phase shape

| # | Phase | Depends on | Proves |
|---|---|---|---|
| 1 | `_template` directive in `compose.py` | — | stk-1 |
| 2 | `generate-images.py` reliability + non-destructive `--out` | — | stk-2 |
| 3 | Schema v6 → v7 + config validation | — | stk-4 |
| 4 | Feature module: `build-sheets.py`, `generate-stickers.py`, gating | 1, 2, 3 | stk-3, stk-4 |
| 5 | **Golden fidelity harness** — the proof | 1, 4 | stk-1 |
| 6 | `tools/migrate_stickers.py` one-time transform | 3, 5 | stk-5 |
| 7 | `manifest.legacy_dests` — retire frank's scripts on `/update` | 4 | stk-5 |
| 8 | Docs, CHANGELOG, version bump, matrix flips | 1–7 | all |

Phases 1, 2 and 3 are independent and touch disjoint files, so they may run in
any order. Phase 5 is the gate: if its 18 goldens are not byte-identical, the
port has failed regardless of what else is green.

All phases are **agentic**. Nothing here needs a secret, a UI action, or a
cluster: no image is ever generated (goldens are prompts; sheets are built from
synthetic PNGs in tests). frank's own adoption — running the transform, pasting
the layer block, `git rm`-ing the remnants — is spec §8 and belongs to frank's
PR, not this plan.

## Two constraints that will bite if forgotten

- **`tools/compose.py` is mirrored** to
  `templates/hugo-hextra/scripts/compose.py`, byte-for-byte, enforced by
  `tests/unit/test_mirrors.py`. Edit the `tools/` copy and re-mirror.
- **`tests/unit/test_image_compose.py` must pass unmodified.** It is the
  regression guard proving no blog's cover prompts shift. If a change to
  `compose.py` requires touching that file, the change is wrong.

## Test invocation

`bash tests/run-unit.sh` prints nothing unless `BLOG_CRAFT_TEST_VENV` points at
a path **off** `/tmp`. Every step's Run line assumes it is exported.
